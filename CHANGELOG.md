# Changelog

## 0.3.1 (2026-09-08)

- Added an installation guide covering prerequisites, source checkout/ZIP setup, prebuilt deployment, optional model preparation, and troubleshooting.
- Added `compose.release.yaml` and `release.env.example` for versioned or digest-pinned deployment from the single canonical `ghcr.io/brntech/lsdf` package, with standard and optional tags.
- Supplied gateway configurations bind to localhost by default and document the separate management and client-authentication boundaries.
- Compose forwards custom-policy and optional-model settings explicitly; vault examples pass required key variables into CLI containers.
- Evaluation reports describe the selected profiles without implying that optional ML profiles were tested.

- Demo readiness waits for healthy upstream status. The local benchmark converter now reports malformed source data safely, records its exact sampling method, and reports language shortfalls without weakening containment expectations.

- Both runtime images default to the dependency-light profile; ML profiles require explicit selection and a prepared cache. Image checks now exercise their own environment-selected profile and the optional worker's pipeline import.
- Prerelease image tags no longer overwrite `latest`; invalid release tags are rejected. Optional runtime checks also run on pull requests.

- Published image targets now start the gateway by default. Runtime images include source, policies, required synthetic foundation fixtures, and three first-party proof matrices; development/evaluation assets remain in separate build targets.
- Existing detector adapters and security features remain Apache-2.0. Heavy detector dependencies remain optional and third-party software, models, and data retain their respective licenses.
- Removed the bundled ai4privacy benchmark and replaced derived regression examples with independently authored fixtures. Licensed local benchmarks can be supplied explicitly; healthcare's benchmark promise is unchanged and missing promised data fails its gate.
- `eval-report` now exits with status 1 when a release gate fails, while still rendering the report.
- Runtime image checks exercise packaging without a source mount and the real HTTP/SSE demo against the image's default gateway command.
- `examples/integrations/runnable_client_examples.py` waits for `/lsdf/health` before posting, so the `litellm-demo` Compose profile no longer races gateway startup in CI.

## 0.3.0

- Foundation test layer separating engine-level capability from profile-level promise. New `tests/foundation/test_detector_recall.py` runs each detector × entity pair in isolation against synthetic fixtures under `tests/foundation/fixtures/<detector_id>/<ENTITY>.json`. ML and contextual pairs carry ≥30 positive + ≥15 negative cases; deterministic regex/entropy/medical-regex/xpia pairs carry 4 positive + 3 negative because their match logic is pinned by focused unit tests. Optional adapter rows (GLiNER, openai_privacy_filter, presidio) run under capability-aware deterministic fakes that consult fixture text via per-entity predicates and can produce false positives on negatives and false negatives on positives lacking the pattern, so aggregate recall and specificity are honest signal rather than 1.0-by-construction. Two-layer test discipline documented in CONTRIBUTING.md so foundation-layer engine contracts and assembly-layer profile promises stay separate; future profile reshuffles re-baseline assembly only.
- New `policies/subtype-emission-manifest.yaml` schema additions: `recall_floor:` and `specificity_floor:` blocks per (detector, entity) pair under a `foundation:` namespace, and `out_of_scope: true` for pairs where this detector_id slot is preempted by an anchored sibling that carries the floor (the inline XML regex matches `<passport>` but `_resolve_contextual_overlaps` collapses dual-emissions to `contextual.identity_document.passport`). Manifest validator hard-errors on declared floor without a matching fixture file, on `recall_floor: 0.0` (replaced by the `out_of_scope` flag), and on `out_of_scope: true` with a floor present in the same entry. Reserved-subtype contract clarified: a reserved entity has no foundation floor until either a baseline detector emits it or an optional ML adapter labels it precisely enough to carry its own contract.
- Per-profile `gate_promise:` blocks land top-level in each release-gated profile YAML, alongside `name:`, `version:`, `detection:`, `action:`, `audit:`. `release_eval.py` reads `gate_promise.corpora`, `gate_promise.recall_floor`, and `gate_promise.specificity_floor` directly from the policy object — no Python-side `RECALL_FLOOR`, `SPECIFICITY_FLOOR`, or `RELEASE_GATED_CORPORA_BY_PROFILE` constants. The declared containment corpora are: `broad-pii` and `broad-pii-ml` each gate their three span-scope promise corpora (`piece_b_replay`, `medical_phi_replay`, `br_agentic_pii`); `healthcare` gates all five (the three plus `nemotron_pii` and `ai4privacy_multilingual`). Floors stay at 0.90 recall / 0.95 specificity.
- New CLI surface `lsdf detectors recall`. Default invocation prints the active-profile foundation summary; `--all` adds the full per-detector × per-entity matrix; `--gaps` adds the engine-aware coverage-gaps table; `--format json` emits the full aggregate report including `floors` and `coverage_gaps`; `--regenerate --output <path>` writes the canonical Markdown artifact. The Markdown summary renders three states per pair: `floor_met`, `floor_missed`, and `out_of_scope` (rendered distinctly so a 0.000 recall against a preempted detector_id slot does not appear as "Floor met = yes"). A `Coverage gaps: N pairs` summary line plus a Gaps section enumerate `(profile, entity)` pairs reachable through release-gated profiles where no in-scope detector declares a non-zero recall floor. The 17 v0.3-shipped engine-aware gaps (BLOOD_TYPE on healthcare without GLiNER; CUSTOMER_CONFIDENTIAL, EMPLOYEE_COMPENSATION, OAUTH_TOKEN, SWIFT, WEBHOOK_URL across the gated profiles) are visible in the artifact without a release-blocking failure.
- New `docs/system-recall.md` artifact regenerated alongside `EVAL.md` from a single canonical pipeline (`scripts/regenerate-artifacts.sh`). New `docs/system-recall-history.jsonl` carries one append-only row per `(detector, corpus, entity)` per CI run with a fixed schema `{timestamp, commit_sha, detector, corpus, entity, recall, specificity, tp, fn, fp, tn}`. `commit_sha` standardizes on 12-char prefixes going forward; the file is raw-value-safe by construction (aggregates only, no fixture text or matched values). EVAL.md gains a cross-reference forward-pointer to the foundation artifact, replacing the v0.2 placeholder. Boundary tests extend to cover the new fixture roots; the regen script sets `GIT_DISCOVERY_ACROSS_FILESYSTEM=1` so Docker Desktop bind mounts produce real commit metadata in artifacts rather than `Commit unknown`.

## 0.2.0

- Two-axis policy schema (no v0.1 compatibility shims). Top-level `detection:` and `action:` blocks replace v0.1's flat structure. `detection:` carries `adapters:`, `entities:`, optional `exclude_engines:`, and per-adapter `settings:`; `action:` carries `mode:` and `rules:`. Mode rename: `enforce | monitor` → `monitor | redact | block`. Action vocabulary cleanup: `allow`, `warn`, `log` retired (`allow` replaced by omitting the rule; `warn`/`log` replaced by `action: redact + on_fail: observe`). `strict.yaml`'s `action: log` rewrites to the new shape. v0.1 policies do not load; no compatibility or migration shim is included.
- New per-rule fields: `scope: span | surface`, `entity_in_category`, `entity_in_category_any_of`, `entity_except`. `scope: span` (default) applies the transform to the matched substring; `scope: surface` applies it to the entire surface payload (useful for compliance-grade whole-output containment). Streaming surfaces (`output.stream_chunk`) reject `scope: surface` at policy-load time. Category-match keys coexist with the pre-existing `entity` and `entity_any_of` on the same rule, allowing expressions like "all PHI subtypes except BLOOD_TYPE" via `entity_in_category: PHI` + `entity_except: [BLOOD_TYPE]`.
- Entity vocabulary split into four categories with subtype-purity emission: `PHI` (MEDICATION, MEDICAL_CONDITION, BLOOD_TYPE, HEALTH_INSURANCE_ID, LAB_VALUE, ICD_CODE, DIAGNOSIS_TEXT, MRN, OTHER_PHI), `SECRET` (AWS_KEY, AZURE_KEY, DATADOG_KEY, JWT, OAUTH_TOKEN reserved, BEARER_TOKEN, PEM_BLOCK, PRIVATE_KEY, DATABASE_URL, WEBHOOK_URL reserved, PASSWORD, API_KEY, OTHER_SECRET), `STRONG_ID` (US_SSN, PASSPORT, DRIVER_LICENSE, NATIONAL_ID, TAX_ID, BR_CPF, OTHER_STRONG_ID), `INTERNAL_ID` (EMPLOYEE_ID, CUSTOMER_ID, STUDENT_ID, USER_ID, LICENSE_PLATE, OTHER_INTERNAL_ID). Detectors emit the most specific subtype they can prove; categories are rule-side constructs only and never emitted as bare entity tags. Standalone canonicals (no category): EMAIL, PHONE, PERSON, ADDRESS, DATE_OF_BIRTH, BANK_ACCOUNT, IBAN, CREDIT_CARD, SWIFT, CUSTOMER_CONFIDENTIAL, EMPLOYEE_COMPENSATION, PROMPT_INJECTION. Catch-all `OTHER_X` naming follows HL7 FHIR / ICD-10 / SNOMED / ISO / NAICS taxonomy convention.
- Subtype-emission manifest at `policies/subtype-emission-manifest.yaml`. Documents per-detector emission contract; validated at policy load with three-state behavior: an `entity:` reference matching a manifest-emitted entity loads normally; a reference to a reserved subtype (OAUTH_TOKEN, WEBHOOK_URL, HEALTH_INSURANCE_ID, EMPLOYEE_COMPENSATION) loads with `RESERVED_SUBTYPE_WARNING` and a fallback-emitter hint; otherwise hard error with a category-suggestion hint ("did you mean `entity_in_category: SECRET`?").
- `contextual-pii` engine split into `contextual-anchored` (baseline) and `contextual-broad` (adapter). Anchored handles inline XML PII tags and narrow label+value patterns for SECRET subtypes and identity documents — high-precision, low-FP-risk, always on. Broad handles label+value patterns for PERSON/ADDRESS/DOB/PHI demographics and output-shape patterns (URL → ADDRESS, IP → ADDRESS, date shape → DOB, username shape → PERSON) — FP-prone on coder traffic, opt-in. `prompt-injection` adapter renamed from internal `xpia` for discoverability; the `xpia` family identifier is preserved in `detector_id` and audit events to keep observability stable.
- `_output_surface_guard` retired in favor of `scope: surface` rules. v0.1 emitted a synthetic whole-surface PHI finding whenever any contextual-pii finding fired on `output.content` — overzealous and detector-family-arbitrary. v0.2 fires whole-output containment only when a rule's entity match hits. The healthcare pack ships `healthcare.phi-output-containment` as the canonical surface-scope rule for compliance-grade containment; other packs can opt in by id.
- Profile renames: `high-recall` → `broad-pii`, `privacy-ml` → `broad-pii-ml`. Names align the detection-tier ladder (`balanced` → `broad-pii` → `broad-pii-ml`) with the two-axis vocabulary. All references in tests, docs, configs, and policy YAMLs updated. Healthcare profile + healthcare pack double-apply rejected at compose-time with a clear error pointing operators at the two correct alternatives.
- CLI discovery surface: `lsdf adapters list`, `lsdf entities list`, `lsdf policy explain`. Reads the manifest and policy summary; `policy explain` reads `docs/performance.md` dynamically rather than hard-coding latency numbers, so doc regeneration cannot drift from CLI text.
- Audit-event schema delta: `scope` (`"span"` or `"surface"`) and `scope_escalated` (bool — true when the action affected the entire surface despite the underlying finding being a substring). Required for downstream observability and `docs/comparative-protection.md` regeneration.
- Eval corpus annotations rewritten to v0.2 vocabulary. `medical_phi_replay.json` labels its 30 cases conservatively (OTHER_PHI when uncertain; specific subtype only when source text contains direct evidence — drug name → MEDICATION, ICD code → ICD_CODE, etc.). `nemotron_pii.json`, `ai4privacy_multilingual.json`, `piece_b_replay.json`, and `br_agentic_pii.json` updated where references used the retired SSN/PHI/SECRET overloaded labels.

- Added four context-anchored PII baseline recognizers — `regex.person_anchored`, `regex.address_anchored`, `regex.date_of_birth_anchored`, `regex.bank_account_anchored` — closing the structural-PII gap that left the dependency-light `default` profile at 0% case-level recall on `PERSON`, `ADDRESS`, `DATE_OF_BIRTH`, and `BANK_ACCOUNT` across the bundled threat corpora. Each follows the same anchor + explicit `[:#=]` delimiter discipline as `regex.national_id_anchored`. Anchor coverage is multilingual: PERSON includes English compound + role-prefixed labels (`First Name`, `Last Name`, `Patient Name`, `Account Holder`, `Speaker`, `Host`), snake_case JSON forms (`first_name`, `given_name`, `family_name`), Dutch (`Voornaam`, `Achternaam`, `Gebruikersnaam`, numbered `Voornaam 1`/`Voornaam 2`), German (`Vorname`, `Nachname`, `Familienname`), Spanish (`Nombre completo`, `Apellido paterno`, `Primer apellido`), Italian (`Cognome`), French (`Prénom`, `Nom de famille`), and bare `Name:` / `Title:` (FP-guarded by case-sensitive value class — only capitalized values match, rejecting benign `File Name: report.pdf`); ADDRESS includes English compound forms (`Street Address`, `Home Address`, `Mailing Address`), snake_case JSON variants, Dutch (`Adres`, `Secundair Adres`, `Woonadres`), German (`Hausanschrift`, `Wohnanschrift`, `Postanschrift`), Spanish (`Dirección postal`, `Domicilio fiscal`), Italian (`Indirizzo`, `Indirizzo postale`), and French compound forms only (`Adresse postale`, `Adresse de résidence`); DATE_OF_BIRTH covers `DOB`, `Date of Birth`, `Birthdate`, `Birthday`, `Geboortedatum`, `Geburtsdatum`, `Fecha de nacimiento`, `Data di nascita`, `Date de naissance`; BANK_ACCOUNT covers `Account Number`, `Bank Account`, `Routing Number`, `Kontonummer`, `Numero di conto`, `Numéro de compte`, `Cuenta bancaria`, `Rekeningnummer`. Per-entity value-class constraints suppress FP differently: PERSON requires capitalized first letter (rejects `File Name: report.pdf`); ADDRESS requires alphanumeric value with literal-space (no `\s`) so newlines terminate before the next labeled field; DATE_OF_BIRTH requires date-shape characters (digits + month-name letters + `./-` separators); BANK_ACCOUNT requires positive-lookahead `≥6 digits` in the captured 6-30 char window (rejects `Account Number: open`). Three additional architectural choices vs `regex.national_id_anchored`: (a) PERSON localizes the case-insensitivity flag via `(?i:...)` so the value-class `[A-ZÀ-ÝŽ]` enforces capitalized first letter — using `(?i)` globally would make the flag bleed into the value class and silently match lowercase values; (b) ADDRESS uses a fixed-width `(?<![A-Za-z\-])` lookbehind to prevent bare `adres` from matching inside `IP-adres` / `E-mailadres` (Python `\b` matches between `IP` and `-adres` because `-` is non-word); (c) BANK_ACCOUNT uses literal space (no `\s`) inside the inner digit-density lookahead to avoid the bounded-but-real ReDoS exposure `\s` would create on long digit-free values. Headline numbers measured on the threat corpora: PERSON case-level recall 13/38 nemotron + 26/51 multilingual; ADDRESS 4/38 + 8/53; DATE_OF_BIRTH 4/11 + 12/29; BANK_ACCOUNT 4/14 + 0/0; zero new findings on `evals/false_positive.json` + `evals/utility_matrix.json`. The default policy currently has only `log` action for PERSON/EMAIL/PHONE and no rules for ADDRESS / DATE_OF_BIRTH, so these new findings lift case-level per-entity recall but do not change the headline value-level redaction recall on the default profile (only BANK_ACCOUNT, which the default policy redacts via `redact-sensitive-identifiers-output`, contributes to value-level lift). Narrative-style PII without an explicit anchor (names in chat transcripts, addresses inline in body text, bracketed `[number]` narrative attributions, bullet-list addresses) is intentionally out of scope for the regex layer; the `privacy-ml` profile's ML detector (OpenAI privacy-filter) covers those. Additional fixes: (a) BANK_ACCOUNT inner lookahead `(?=(?:[A-Za-z0-9.\-\s]*\d){6,})` had bounded ReDoS exposure on 30-char digit-free values — replaced `\s` with literal space consistent with the rest of the value class; (b) the comment block called `privacy-ml` an "NER detector" when it's an ML output classifier (OpenAI privacy-filter) — corrected to "ML detector"; (c) added the single-letter rejection test, pinned-confidence test, and the known-FP regression-pin test.
- Added `regex.national_id_anchored` recognizer for international national-ID values across six locales, closing the SSN-recall gap left by the existing US-only `regex.ssn` recognizer (`\b\d{3}-\d{2}-\d{4}\b`). Anchor alternation covers Dutch (`BSN`, `Burgerservicenummer`, `Sociaal nummer`, `Sofinummer`), generic English (`Social Security Number`, `Social Number`, camelCase `SocialSecurityNumber`, `Numéro_Social`), French (`Numéro de sécurité sociale`, `NIR`, `INSEE`, `sécurité sociale`), Italian (`codice fiscale`, `\bCF\b`, `Numero di sicurezza sociale`, `Numero di previdenza sociale`), German (`Steuer-ID`, `Steueridentifikationsnummer`, `Steuernummer`, `Sozialnummer`, `Sozialversicherungsnummer`), Spanish (`DNI`, `NIE`, `documento de identidad`, `número de seguridad social`, `seguridad social`), and UK (`NINO`, `National Insurance number`). The regex requires an explicit `[:#=]` delimiter between anchor and value — narrative-style "Social Security Number is 212-92-7506" deliberately falls through to the existing US `regex.ssn` recognizer because extending tolerance to "is"/"of" prepositions invites FP on benign prose. Value class permits alphanumeric + space + dot + dash with an inner negative lookahead `(?! \- )` that terminates the match at the space-dash-space field-separator pattern used by the bundled multilingual corpora ("…D33 8 - Adresse: …" no longer absorbs the next field). Markdown-asterisk anchors (`*Social Number:*`) and JSON-quoted forms (`"Social Number":"value"`) are tolerated via a unified pre-/post-delimiter quote/asterisk class. Checksum validation is intentionally skipped — the bundled threat corpora generate national-ID values structurally without honoring real-world checksums (luhn, mod-11, mod-23), so a strict checksum would zero-out recall on the synthetic data while the anchor + delimiter gate keeps benign-FP load at zero. Headline numbers measured against `evals/ai4privacy_multilingual.json` + `evals/nemotron_pii.json` + `evals/piece_b_replay.json`: combined SSN case-level detection lifts from 7/36 (0.194) to 27/36 (0.750) — a 3.86× recall multiplier with zero new findings on `evals/false_positive.json` or `evals/utility_matrix.json`. ai4privacy multilingual specifically: 22 of 31 SSN-tagged cases now anchor-detected (was 0 — only 2 caught via narrative US-shape), spanning all six target languages. New `tests/test_regex_national_ids.py` (26 tests) pins per-locale anchor coverage (Dutch BSN-nummer / Burgerservicenummer / Sociaal nummer; French SocialSecurityNumber camelCase + Numéro_Social underscore JSON; Italian codice fiscale + Numero di sicurezza sociale + previdenza sociale; German Sozialnummer + Sozialversicherungsnummer; Spanish underscore-JSON form), markdown-asterisk anchor tolerance, the 6-char minimum / 30-char maximum value boundary, the field-separator negative-lookahead terminating at ` - ` while preserving codice-fiscale-shaped values with embedded dashes, two-anchors-in-one-document independence, IBAN-shaped value collision with `regex.iban` (both detectors fire; overlap resolution stays in `DetectorRegistry`), and three negative cases for benign acronyms (`cf.` Latin abbreviation, `NIR` study group, `DNI` system) that must NOT fire without the `[:#=]` delimiter. - Added Presidio-anonymizer-parity operator vocabulary: `replace`, `hash`, `encrypt`. The bundled action set was `allow | warn | log | redact | mask | tokenize | block`; the new operators carry per-rule parameters validated at policy load. (a) `replace` requires `replacement: <string>` and emits the operator-supplied literal verbatim — useful for stable named placeholders like `[CUSTOMER]` or `<<EMAIL>>`. (b) `hash` accepts an optional `hash_algo` from `{sha256, sha512, blake2b}` (default `sha256`) and emits `<{ENTITY}:HASH:<algo>=<hex16>>`; deterministic so audit events and traces correlate without revealing the raw value. The hex digest is truncated to 16 characters (64 bits) by design — birthday-collision space at 64 bits is ~2^32, well above the cardinality of typical sensitive values, and the truncation trades collision-resistance for in-line readability.
